# sccache 的 IAR 编译器支持（第一阶段）

本文说明这个 fork 在上游 sccache `v0.18.0` 之上为 IAR C/C++ 编译器（`iccarm` 等）增加的缓存支持：做了什么、怎么用、验证到什么程度、有哪些已知限制。

- 基线：上游 `v0.18.0`（`01c35e6`）
- 本 fork 版本号：`0.18.0-iar.1`
- 验证环境：Linux，`iccarm` 9.60.4（IAR Build Tools for Arm），CMake 3.28 + Ninja

## 1. 一句话结论

同一目录下重复编译同样内容时，sccache 直接取回上次的目标文件，不再调用 `iccarm`。在一个 1626 个编译单元的固件工程上，全部命中时重编用时从 49.5 秒降到 4.4 秒，取回的 `.o`、链接出的 `.elf` 与不用缓存时逐字节一致。首次编译（全部未命中）会比不用缓存慢约 10 秒。

## 2. 适用范围

| 项目 | 状态 |
|---|---|
| 同一路径下的本地磁盘缓存 | 支持，已验证 |
| 不同路径之间共享缓存（不同 worktree、不同机器） | 不在第一阶段目标内，未验证 |
| 分布式编译（sccache-dist） | 不支持 |
| `iccarm` 以外的 IAR 编译器（`iccrx`、`iccriscv` 等） | 探测逻辑按名字覆盖，但没有实测 |
| IAR 汇编器 `iasmarm` | 不缓存，原样执行 |
| Windows | 未验证 |

## 3. 使用方法

### 3.1 安装

```bash
cargo install --path . --locked     # 装到 ~/.cargo/bin/sccache
sccache --version                   # 应输出 sccache 0.18.0-iar.1
```

### 3.2 接入 CMake 工程

配置时把 sccache 设为编译器的 launcher：

```bash
cmake ... -DCMAKE_C_COMPILER_LAUNCHER=$(command -v sccache) \
          -DCMAKE_CXX_COMPILER_LAUNCHER=$(command -v sccache)
```

已经配置过的构建目录需要重新配置才会生效。官方原版 sccache 不认识 `iccarm`，接入脚本应检查 `sccache --version` 的输出里带 `-iar` 再启用。

### 3.3 常用开关

| 环境变量 | 作用 | 生效时机 |
|---|---|---|
| `SCCACHE_DIR` | 缓存目录，默认 `~/.cache/sccache` | 服务启动时 |
| `SCCACHE_CACHE_SIZE` | 缓存上限，默认 10 GiB | 服务启动时 |
| `SCCACHE_DIRECT=false` | 关闭清单模式（见 4.5），每次都跑预处理 | 每次调用 |
| `SCCACHE_RECACHE=1` | 忽略已有缓存，强制重新编译并刷新（IAR 上未实测） | 每次调用 |

查看统计：`sccache --show-stats`，IAR 的条目显示为 `c [iar]` / `c++ [iar]`。

## 4. 实现说明

### 4.1 改动清单

| 文件 | 改动 |
|---|---|
| `src/compiler/iar.rs` | 新增。IAR 后端：探测、参数解析、预处理、编译命令生成，以及单元测试 |
| `src/compiler/compiler.rs` | 在通用探测之前加 IAR 探测分支；统计显示名；一个探测测试 |
| `src/compiler/c.rs` | 新增 `CCompilerKind::Iar`；环境变量白名单加入 `C_INCLUDE`、`QCCARM` |
| `src/compiler/preprocessor_cache.rs` | 清单模式的环境变量白名单加入 `C_INCLUDE`、`QCCARM` |
| `src/compiler/mod.rs` | 声明 `iar` 模块 |
| `Cargo.toml`、`Cargo.lock` | 版本号改为 `0.18.0-iar.1` |

### 4.2 编译器探测

sccache 的通用探测是用 `-E` 预处理一段测试代码并读 stdout。IAR 编译器没有 `-E`，预处理结果也只能写到文件，所以通用探测识别不了。

做法：可执行文件名形如 `icc<目标>`（`iccarm`、`iccrx` 等，Intel 的 `icc` 不算）时，先运行 `--version`，输出的首个非空行以 `IAR ` 开头且包含 `Compiler` 才认定为 IAR，并把这一行作为版本信息。不满足时落回通用探测，其他编译器不受影响。

### 4.3 整条命令行原样保留

`iccarm` 会把完整的命令行写进目标文件的 `.comment` 段。因此参数的写法、顺序、`-o` 路径、依赖文件路径都会改变 `.o` 的字节内容。

为了让命中的结果与直接编译逐字节一致：

- 整条原始命令行进入缓存键；
- 未命中时用原始命令行原样执行编译，不重排、不规范化。

实现上把原始参数整体放在 `ParsedArguments::arch_args` 里，这个字段会被哈希；`common_args`、`preprocessor_args` 留空。参数表只用来区分"带独立取值的选项"和"输入文件"。

### 4.4 预处理与依赖文件

- 预处理命令是"原始命令行 + `--preprocess=n <临时文件>`"，然后读回临时文件作为预处理输出。
- 原始命令行里若有 `--dependencies`，预处理这次调用会同时写出依赖文件，内容与编译阶段写出的一致，并且不会产生目标文件。这是必须的：sccache 在"做过本地预处理"的命中路径上不会从缓存恢复依赖文件，而是认为预处理阶段已经生成了它。

### 4.5 清单模式（预处理缓存模式）

这是 sccache 已有的通用功能，使用本地磁盘缓存时默认开启，IAR 后端没有禁用它。它在按预处理结果查缓存之前加了一层快速通道：

| 情况 | 行为 | 调用 `iccarm` |
|---|---|---|
| 源文件、命令行、清单里记录的所有头文件都没变 | 直接命中，目标文件和依赖文件都从缓存恢复 | 0 次 |
| 有文件变了 | 跑预处理，按预处理结果查缓存 | 1 次预处理；仍未命中再加 1 次编译 |
| 从没见过这个源文件 | 跑预处理建清单，然后编译 | 1 次预处理 + 1 次编译 |

清单里的头文件列表来自预处理输出中的行标记。`iccarm` 输出的是 `#line N "路径"` 格式，sccache 的扫描器支持这种格式。

### 4.6 影响编译的环境变量

`iccarm` 会读取 `QCCARM`（追加命令行选项）和 `C_INCLUDE`（追加头文件搜索目录）。两者已加入缓存键。其他目标的 IAR 编译器使用各自的变量名，没有加。

### 4.7 不缓存、直接透传的情况

| 情况 | 原因 |
|---|---|
| `-f`、`--f` | 参数来自响应文件 |
| `--preprocess`、`--predef_macros` | 不是普通的编译 |
| `-l...` 列表文件、`--diagnostics_tables` | 有未跟踪的额外输出 |
| `--mfc` 或多个输入文件 | 多文件编译 |
| `-o` 或 `--dependencies` 指向目录，或 `--dependencies` 取值为 `+` | 输出文件名由编译器决定 |
| 无法从扩展名判断语言的输入 | 同其他后端 |
| `--version` | 不是编译 |

## 5. 验证结果

以下数据都来自同一工程（1626 个 `iccarm` 编译单元，Release 配置）在同一台 32 核机器上的实测。

### 5.1 速度

删掉全部目标文件后重新构建（含链接）：

| 场景 | 用时 | 命中 / 未命中 |
|---|---|---|
| 不经 sccache | 49.5 s | — |
| 清单模式（默认） | 4.4 s | 1626 / 0 |
| `SCCACHE_DIRECT=false`，每次都预处理 | 14.3 s | 1626 / 0 |

首次完整构建（含代码生成，缓存为空）：经 sccache 约 69 秒；工程维护者另行测得不用缓存 63 秒、用缓存 73 秒。多出的时间是未命中时每个单元多跑的一次预处理。

一套构建配置的缓存占用约 49 MiB。

### 5.2 正确性

- 上表三种场景以及首次构建，全部 `.o`、最终 `.elf`、Ninja 记录的头文件依赖，哈希完全相同。
- 修改一个头文件后，Ninja 能正确判定需要重编的单元（依赖记录没有丢）。
- 用 sccache 自己的扫描器解析 60 个真实编译单元的预处理输出，得到的头文件集合与 `iccarm --dependencies=n` 给出的完整清单逐一比对：30271 个引用，全部一致。空头文件、整个被 `#if 0` 屏蔽的头文件、只有注释的头文件、重复包含的头文件，`iccarm` 都会输出行标记。
- 单元测试：编译器模块 351 个全部通过，其中 13 个为 IAR 新增。

### 5.3 逐项行为

| 情况 | 结果 |
|---|---|
| 什么都没变 | 清单命中，产物正确 |
| 头文件改了内容 | 重新编译，产物正确 |
| 头文件行内加注释 | 预处理后命中，产物正确 |
| 头文件新增一行注释 | 重新编译，产物正确（`iccarm` 把注释行保留为空行，预处理结果变了） |
| 源文件含 `__TIME__` 等时间宏 | 自动退出清单模式 |
| 用 `QCCARM` 切换优化级别 | 各自独立缓存，产物正确 |
| `C_INCLUDE` 换目录 | 重新编译 |

## 6. 已知限制

### 6.1 清单模式的盲区（会误命中）

清单只记录"实际用到的文件"。下面两种情况，清单里的文件都没变，但编译结果本应不同：

1. 在搜索顺序更靠前的目录里**新增**了一个同名头文件；
2. `__has_include` 探测的文件原来不存在，后来出现了。

已用 `iccarm` 实测确认第 1 种会取回旧的目标文件，且不会自愈：旧清单一直有效，直到被遮蔽的那个旧头文件发生变化或缓存被清掉。这是 sccache 清单模式的固有局限，上游文档 `docs/Local.md` 同样列出了它，ccache 的同类模式也一样。

规避办法：对结果要求严格的构建（出包、提测）设 `SCCACHE_DIRECT=false`。此时每次都跑预处理，实测上述情况结果正确，代价是全命中用时从 4.4 秒回到 14.3 秒。

### 6.2 首次编译变慢

未命中时每个单元多一次预处理，整体慢约 10 秒。这是按预处理结果做缓存的固有代价。

### 6.3 其他

- `--dlib_config` 指向的配置文件只有路径进入缓存键，文件内容没有单独哈希。
- 只有 `QCCARM` 被加入缓存键，`QCCRX` 等其他目标的同类变量没有。
- 命中时不调用 `iccarm`，因此也不会重新向许可服务器签出许可。

## 7. 没有做的事（后续阶段候选）

| 事项 | 说明 |
|---|---|
| 冷启动捷径 | 从没见过的源文件直接编译，编译后用依赖文件建清单，省掉首次的预处理。需要改 sccache 的公共流程 |
| 目录列表防护 | 记录各搜索目录的文件名列表以缩小 6.1 的盲区。sccache 和 ccache 都没有这个机制 |
| `--dlib_config` 文件内容进缓存键 | 小改动 |
| 跨路径命中 | 需要路径归一；已知两个不同目录下同一提交的预处理输出在路径归一后完全相同，但取回的 `.o` 里调试路径会是原目录的 |
| Windows、其他 IAR 目标 | 未验证 |
